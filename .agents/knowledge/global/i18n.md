# Internationalization & Multi-Language Architecture

## Purpose

Establishes system-wide internationalization (i18n) invariants across all communication surfaces (Web Dashboard, zalo Bot, notifications, automated calls, HTML templates, Gemini user-facing outputs, and client error messages). Guarantees consistent localization, eliminates untranslated hardcoded literals, and maintains strict typing for translation keys.

## Supported Locales & Fallback Policy

- **Supported Locales**: `vi` (Vietnamese - Default) and `en` (English).
- **Fallback Hierarchy**: If a user locale is missing, invalid, or untranslated, fallback to `vi`.
- **Locale Resolution**:
  - **zalo Bot**: Persisted in `users.preferredLocale`. Evaluated on demand at command intake, response rendering, and scheduled reminder dispatch.
  - **Web Dashboard**: Persisted in the `zalobot-locale` cookie. Evaluated in Next.js providers and root layout attributes (`<html lang="...">`).
- **Number & Date Formatting**: Formatted dynamically using `localeTag(locale)` (e.g. `'vi-VN'` vs `'en-US'`) while server business time calculations remain pinned to `'Asia/Ho_Chi_Minh'`.
- **Gemini JSON Context**: Every Gemini JSON-producing flow receives the current `DEFAULT_TIMEZONE` anchor. Chat/tool-call JSON receives it through the system instruction; direct OCR JSON receives it in its dedicated prompt.

## Invariants & Strict Rules

1. **Zero Hardcoded User-Facing Literals**:
   - Hardcoded string literals for any user-facing text (JSX children, buttons, placeholders, table column headers, panel titles/descriptions, empty messages, aria labels, zalo messages, toasts, alerts, metadata, HTML templates) are strictly prohibited.
1. **Centralized Message Contracts**:
   - All translation message keys, supported locales, and dictionary mappings reside in `@zalobot/contracts` (or shared module catalog).
   - Every translation key MUST exist in both `vi` and `en` dictionaries.
1. **Dynamic Interpolation Parameterization**:
   - Dynamic user data (names, dates, amounts) MUST be passed via named template parameters (e.g., `{userName}`, `{amount}`) into `translate(locale, key, values)` or `t(key, values)`.
1. **Locale-Aware Formatting & Fallbacks**:
   - Format numbers/currency via `Intl.NumberFormat(localeTag(locale), ...)` and dates via `Intl.DateTimeFormat(localeTag(locale), ...)`.
   - Use localized fallback keys (e.g., `t('common.notSet')`) instead of hardcoded strings like `'Chưa đặt'` or `'—'`.
1. **Technical Identifier Allow-List**:
   - Technical identifiers MUST NOT be translated: zalo callback data (`ACTION_*`), API routes (`/api/...`), database table/column names, internal log strings, tool names, network protocols, and third-party error codes.

## Cross-Channel Integration Points

- **zalo Bot**:
  - Command `/language` presents locale switcher inline keyboard (`web.language.vi`, `web.language.en`).
  - Scheduled reminders resolve receiver's `preferredLocale` at dispatch time and format notification headers accordingly (`reminder.header.text`, `reminder.header.call`).
- **Dashboard Web UI**:
  - Locale provider (`LocaleProvider`) exposes `locale`, `setLocale`, and helper `t(key, values)`.
  - Navigation items, metric labels, action buttons, panel headers, table columns, and loading/error/empty states resolve through the shared contract catalog.
