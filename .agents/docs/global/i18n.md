# Hướng Dẫn Vận Hành & Sử Dụng Đa Ngôn Ngữ (i18n)

Tài liệu này hướng dẫn quản lý và bổ sung đa ngôn ngữ trong Zalobot, ánh xạ với tri thức canonical [`i18n.md`](../../knowledge/global/i18n.md).

## 1. Nguyên Tắc Hoạt Động & Ngôn Ngữ Hỗ Trợ

- **Ngôn ngữ hỗ trợ**: `vi` (Tiếng Việt - mặc định) và `en` (English).
- **Fallback**: locale sai hoặc thiếu → `vi`; key chưa có bản dịch → dùng bản `vi`, nếu vẫn thiếu thì trả về chính key (dễ phát hiện khi test).
- **Lưu trạng thái**:
  - **Web Dashboard**: cookie `zalobot-locale` (1 năm). `LocaleProvider` đọc cookie khi mount; đổi ngôn ngữ bằng ô chọn trong thanh điều hướng, khi đó thuộc tính `lang` của `<html>` được cập nhật thành `vi-VN`/`en-US`.
  - **Zalo Bot**: trường `users.preferredLocale` (mặc định `vi`). Hiện chỉ bộ lập lịch nhắc nhở đọc trường này để chọn tiêu đề tin nhắc và định dạng giờ. Chưa có lệnh bot nào cho phép người dùng đổi ngôn ngữ.
  - **Prompt cho LLM**: mọi lần gọi `LlmService` đều kèm mốc ngày giờ hiện tại theo `DEFAULT_TIMEZONE`, để AI quy đổi đúng "hôm qua", "tối mai"...

## 2. Quy Chuẩn Thêm & Quản Lý Translation Keys

Toàn bộ key nằm trong `packages/contracts/src/index.ts` (`@zalobot/contracts`):

1. **Khai báo song ngữ bắt buộc**: thêm key mới phải có nội dung trong cả `messages.vi` và `messages.en`. Kiểu `TranslationKey` sinh từ catalog nên gõ sai key sẽ lỗi typecheck.
2. **Nội suy**: dùng `{variableName}` và truyền qua `translate(locale, key, values)` hoặc `t(key, values)`.
3. **Định dạng số/ngày**: dùng `localeTag(locale)` với `Intl.NumberFormat`/`Intl.DateTimeFormat`. Múi giờ nghiệp vụ luôn là `Asia/Ho_Chi_Minh`.

## 3. Bề Mặt Áp Dụng

### Bắt buộc dùng i18n

- **Web Dashboard**: text JSX, nhãn nút, placeholder, tiêu đề cột `DataTable`, tiêu đề/mô tả `DataPanel`, trạng thái rỗng/lỗi, `aria-label`, chuỗi fallback (`t('common.notSet')` thay vì `'Chưa đặt'`).
- **Trang public** (`/about`, `/privacy`, `/terms`) và metadata.
- **Tin nhắn bot mới** và thông điệp lỗi API hiển thị trực tiếp cho người dùng.

### Hiện trạng cần biết

Phần lớn tin nhắn bot trong `apps/api/src/zalo/text/strategies/` và thẻ xác nhận vẫn là chuỗi tiếng Việt viết trực tiếp; API mới chỉ dùng `translate` cho tiêu đề tin nhắc. Khi sửa hoặc thêm phản hồi bot, ưu tiên chuyển sang key trong catalog.

### Ví dụ chuẩn trong React component

```tsx
import { useLocale } from '@/shared/providers/locale-provider';
import { localeTag } from '@zalobot/contracts';

export function MyScreen() {
  const { t, locale } = useLocale();

  const formattedDate = (value?: string) =>
    value ? new Intl.DateTimeFormat(localeTag(locale)).format(new Date(value)) : t('common.notSet');

  return (
    <DataPanel title={t('debts.panel.title')} description={t('debts.panel.description')}>
      <DataTable
        ariaLabel={t('debts.table.ariaLabel')}
        emptyMessage={t('debts.table.empty')}
        columns={[
          {
            id: 'counterparty',
            header: t('debts.columns.counterparty'),
            cell: (row) => row.counterparty,
          },
        ]}
        rows={[]}
      />
    </DataPanel>
  );
}
```

### Ngoại lệ kỹ thuật (không dịch)

- Log hệ thống (`logger.log`, `console.error`...).
- Đường dẫn API và route (`API_ROUTES.*`, `APP_ROUTES.*`).
- Tên tool LLM (`TextToolType`), cú pháp xác nhận (`yes <code>`, `cancel <code>`).
- Tên bảng/cột cơ sở dữ liệu, enum kỹ thuật, mã lỗi nội bộ.
- Dữ liệu người dùng nhập hoặc dữ liệu bên thứ ba (Google Workspace, hồ sơ Zalo).

## 4. Kiểm Tra

- `npm run typecheck`: phát hiện key không tồn tại trong catalog.
- Rà soát thủ công: chuyển ngôn ngữ sang `en` trên dashboard và kiểm tra không còn chuỗi tiếng Việt cứng. Hiện chưa có validator tự động quét chuỗi hardcode.
